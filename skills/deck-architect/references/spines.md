# Narrative spines

State which spine you picked and why before outlining.

## SCQA + Pyramid (Minto) — for executive / business / recommendation decks

- **Situation** — uncontroversial current-state context the audience already accepts
- **Complication** — what changed, what's at stake, why now
- **Question** — the decision question that naturally follows
- **Answer** — the recommendation, stated directly. This is slide 1 of the body.
- Then 2–4 supporting arguments, each with evidence
- Arguments must be **MECE** — Mutually Exclusive (no overlap), Collectively Exhaustive (cover the territory). If two arguments restate the same point, collapse them.

## Hook → Problem → Insight → Evidence → Takeaway — for technical talks / conferences

- **Hook** — sharp problem statement, surprising stat, or vivid example
- **Problem** — define the pain, who it affects, why existing approaches fall short
- **Insight / Approach** — the core idea, a single technical claim, not a survey
- **Evidence** — minimum proof needed (benchmarks, demos, case)
- **Takeaway** — what the audience should do or build differently on Monday

Time budget: ~15% hook/intro, 60–70% body, 15–20% demo + close.

## Problem → Why Now → Solution → Why Us → Proof → Ask — for pitch decks

Use only when explicitly pitching for funding, a sale, or a decision to partner.

## Headline → What changed → What it means → What's next — for updates / status

Resist the urge to walk through every workstream. Headline first, details on tap.

---

If the user's situation doesn't fit cleanly, pick the closest and adapt — but state the adaptation.
