# Great skills refuse. Average skills suggest.

## Audience Model
- **Who's in the room:** Claude Code power users who have already written at least one production skill and can read frontmatter fluently. Hardest sell: the author of an eight-skill personal catalogue who is about to decide every line of this talk applies to everyone's skills but theirs. Second-hardest: the minimalist who treats any ban list as bloat. `[INFERRED — confirm]`
- **What they care about:** does the skill actually fire when it should, and when it fires does the output change in a way they can measure on their own laptop. Token cost is a secondary worry they surface when pushed. `[INFERRED — confirm]`
- **What they already know/believe:** how Claude loads skills, that the `description` field drives invocation, that long SKILL.md files chew context. They believe their own skills are fine. They do not yet distinguish a skill that *instructs* from a skill that *refuses*. `[INFERRED — confirm]`
- **Transformation (walk-in → walk-out):** "This is a book review of someone else's skills" → "I know four moves, I can make the cheapest one this afternoon, and I have a 72-hour check that tells me whether I broke triggering."
- **Likely objections / deep-dive triggers:**
  1. "Why these two and not Anthropic's first-party library?"
  2. "Twelve rebuttal rows inflates context on every load — what does that cost?"
  3. "Naming defaults is obvious for a visual skill. What does it look like for a testing skill or a docs skill?"
  4. "One person, twelve sessions is thin evidence for a main-flow chart."
  5. "If the enforcement pass tanks triggering, how fast do I find out?"

## Brief
- **Decision/ask:** pick one skill you already own, apply Move 1 (name the default you want killed), wire the 72-hour invocation-count check, ship before Friday.
- **Format & time:** 12-minute live talk plus ~5 minutes Q&A. Power-user / late-morning technical-conference register.
- **Constraints:** 11 main slides plus 5 backup. Self-contained HTML. No corporate template.
- **One-sentence takeaway:** **A skill earns its keep by refusing the model's specific defaults — not by describing behaviours you wish it had.**
- **Team contributors:** N/A — single-author analysis of two third-party skills.

## Narrative spine
**SCQA + Pyramid (Minto).** The audience wants the answer on slide 1 and evidence behind it, not a guided tour. Four moves, four supporting slides (with slide 6 carrying the chart and slide 7 carrying the mechanism — v4 tried to combine and the chart had to share its oxygen). Honest cost, rollback, ask. A tool-tour spine would lose the room before the reframe.

## Cover slide
- **Title:** *Great skills refuse. Average skills suggest.*
- **Subtitle (≤12 words):** *Lessons from impeccable and superpowers, for authors of other skills.* (11 words, same voice, no second argument introduced)
- **Meta:** *Power-user talk · 12 min*

One `<h1>`, one subtitle, one neutral meta row. No kicker eyebrow, no continuation word. Reads as one deck name in one breath: two four-word sentences in antithesis, then a one-line context row. The contrast in the title itself is what makes it quotable — "refuse / suggest" is the sentence the audience will paraphrase when someone asks them what the talk was about.

## Opening hook (first 30 seconds)
*"The two community skills that changed how I ship stopped telling Claude what to do. One bans the eleven fonts it reaches for by default. The other pre-empts the fourteen excuses it uses to skip tests. And one of them ships a node script that grades the output with no model in the loop. That is the move — and the gap between a skill you wrote for yourself and a skill people install."*

Spoken, not displayed. The hook and STAR land on the same idea: the best community skills are enforcement systems dressed as capability skills, concretized by the model-free auditor shipping inside a so-called design skill. No separate manufactured peak.

## STAR moment
Slide 2, the reframe: both skills look like capability additions and are in fact discipline-enforcement systems wrapped around known model defaults. "Enforcement systems dressed as capability skills" is the hallway-repeatable line.

9. **What you give up: longer files, sharper edges, real authoring time.**
   - Purpose: tradeoff. A deck without one reads as a sales pitch.
   - On-slide: three honest costs in parallel. (1) SKILL.md roughly doubles when you add a ban list and a rebuttal table — a twenty-line skill becomes forty lines before measurement. (2) Opinionated skills fight the user on edges — enforcement cuts both ways, you need an override path and the discipline to use it when the user is right. (3) The first pass is weak and you have to live with it — you cannot write a ban list for a domain you have not lived in; the skill sharpens only with invocation data, budget for version two.
   - Speaker notes: the smallest useful version is one banned token plus one rebutted excuse. Twenty authoring minutes, not a weekend. Address the "sounds heavy" instinct directly — the audience is thinking it before you say it. Name the skill you are *not* going to apply this to this quarter and why — if the skill has fewer than five real invocations, you are guessing at the ban list and will ban things you later need.
   - Load: balanced
   - Visual: text-only

10. **If this backfires, catch it in 72 hours — not next sprint.**
    - Purpose: rollback in main flow. This is a decision deck asking for a change to a working artifact.
    - On-slide: two blocks. Left block — the 72-hour check as three steps: (A) keep the prior SKILL.md as `SKILL.md.prev` next to the new one, one-line diff is your rollback; (B) log invocation count for 72 hours after the change; (C) if invocations drop by more than 30% against the trailing week, triggering regressed — restore, diagnose, retry. Right block — three "when not to do this" constraints: no enforcement on skills with fewer than five real invocations; no ban without a specific replacement; if enforcement consistently fights user intent, the user wins every time.
    - Speaker notes: anticipate the "I won't notice regressions for a week" objection head-on. The 72-hour check is cheap, survives being forgotten, and catches the failure mode of a ban list with no replacement. Thirty percent is a practitioner heuristic, not a controlled number — if someone pushes, flag that honestly; the point is the existence of a pre-committed threshold, not its exact value.
    - Load: slide-heavy
    - Visual: text-only

    - On-slide: the takeaway — *A skill earns its keep by refusing the model's defaults, not by describing behaviours you wish it had.* — at display size, one visual line. Underneath, three words as the action line: **Pick.** **Ban.** **Check.** Each tagged with a one-line follow: *a skill you already own* / *one specific token — start with Move 1* / *invocation count, 72 hours, 30% threshold*. Everything fits in three lines total below the takeaway.
    - Speaker notes: the deck succeeds when the audience names a skill aloud. Ask for one out loud before the room moves on — public commitment is what makes Friday happen. "Pick, Ban, Check" is a memory aid; each maps to Move 1 and the 72-hour check. If the room is early-career, offer to help someone in the Q&A pick which skill and which token.
    - Load: balanced
    - Visual: text-only

## Pressure-test log [size: Standard]

**Role adopted:** experienced Claude Code skill author, eight-to-twelve skills in their personal catalogue, six months of active use, mildly defensive about being told their skills need teeth.
